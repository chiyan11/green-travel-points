## 2. 本机环境的两处非默认配置（容易踩坑）

1. **配置文件不在 ProgramData**：服务启动参数是
   `mysqld --defaults-file="D:\coding\mysql\my.ini" MySQL97`，
   因此改端口/字符集要去 `D:\coding\mysql\my.ini`，不在 `C:\ProgramData\MySQL\`。
2. **datadir 在 D 盘**：`D:/coding/mysql/Data`，日志 `DESKTOP-IGAKB82.err` 也在该目录。
   另外 `lower_case_table_names=1`（表名落盘小写）与
   `sql-mode` 含 `ONLY_FULL_GROUP_BY`——P3 写聚合查询时要留意。

## 3. root 怎么连（本机没有明文密码）

`root@localhost` 的密码未知，但 **MySQL Workbench 保存了凭据**，
其自带 `mysqlsh` 用这份凭据可以免密以 root 执行 SQL：

```powershell
$sh = 'D:\coding\mysql\MySQL Workbench\resources\app\shell\bin\mysqlsh.exe'
$env:MYSQLSH_USER_CONFIG_HOME = "$env:APPDATA\MySQL Workbench\mysqlsh"
& $sh --sql --uri "root@localhost:3306" -e "SELECT CURRENT_USER(), VERSION();"
```

这条路径只在本机（有 Workbench 凭据）有效。**组内其他机器用自己的 root 密码**执行
README「1. 数据库准备」里的建库建号 SQL 即可，效果等价。

## 4. 实际执行过的命令

```powershell
# ① 建库 + 建账号（root 身份，经 mysqlsh）
$sql = @"
CREATE DATABASE IF NOT EXISTS green_travel_points DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'greentravel'@'localhost' IDENTIFIED BY 'greentravel';
CREATE USER IF NOT EXISTS 'greentravel'@'127.0.0.1' IDENTIFIED BY 'greentravel';
CREATE USER IF NOT EXISTS 'greentravel'@'%' IDENTIFIED BY 'greentravel';
GRANT ALL PRIVILEGES ON green_travel_points.* TO 'greentravel'@'localhost';
GRANT ALL PRIVILEGES ON green_travel_points.* TO 'greentravel'@'127.0.0.1';
GRANT ALL PRIVILEGES ON green_travel_points.* TO 'greentravel'@'%';
FLUSH PRIVILEGES;
"@
& $sh --sql --uri "root@localhost:3306" -e $sql

# ② 按文件名顺序执行两条 up 迁移（应用账号身份，验证授权可用）
Get-ChildItem db\migrations\*.up.sql | Sort-Object Name | ForEach-Object {
  Get-Content $_.FullName -Raw -Encoding UTF8 |
    mysql -h 127.0.0.1 -P 3306 -u greentravel -pgreentravel --default-character-set=utf8mb4 green_travel_points
}

# ③ 启动后端验就绪探针
. .\scripts\dev-env.ps1                      # 受限环境必须，否则 go 报 Access is denied
cd apps\api; go build -o ..\..\.cache\api-dev.exe .\cmd\server; ..\..\.cache\api-dev.exe
```

## 5. 应用侧怎么配（不需要改代码）

后端从环境变量读 `DB_DSN`，缺省值就是
`greentravel:greentravel@tcp(127.0.0.1:3306)/green_travel_points?parseTime=true&loc=Local&charset=utf8mb4`
（见 `apps/api/internal/config/config.go` 的 `DefaultDatabaseDSN`）。
所以本机装好库之后 **不用建 `.env`** 也能直连；要连别的库，直接设置环境变量（后端不解析 `.env` 文件）：

```powershell
$env:DB_DSN='greentravel:greentravel@tcp(主机:3306)/green_travel_points?parseTime=true&loc=Local&charset=utf8mb4'
```

`sql.Open` 不建立真实连接（`internal/repo/repo.go`），因此「服务起得来」不代表「库通了」，
**以 `/readyz` 为唯一判据**。

## 8. 跨网共享（ZeroTier，不同网络 / 校外 / 手机热点）

### 8.1 为什么用它

ZeroTier 是**覆盖网络**（虚拟局域网）：成员装客户端后拿到 `10.x.x.x` 地址，组员之间像同一网段，**3306 不暴露到公网**。比端口映射（frp / ngrok）安全，比买云主机省事。

### 8.2 网络参数

| 项 | 值 | 谁需要 |
| --- | --- | --- |
| Network ID（16 位） | `743993800f43676f` | 所有成员，Join 时填 |
| 主机 ZeroTier 地址 | `10.213.180.114/24` | 组员填进 DSN |
| 主机 Node ID（10 位） | `0bab0cb69b` | 管理员核对用 |
| 组员 Node ID | 每人一串 10 位，报给管理员 | 管理员在控制台 Members 勾 **Auth** |

> 16 位是 Network ID，10 位是 Node ID，长度差一倍，别互相等。

### 8.3 主机侧（管理员 PowerShell 执行一次）

```powershell
New-NetFirewallRule -DisplayName "MySQL 3306 (ZeroTier)" -Direction Inbound -Protocol TCP -LocalPort 3306 -Action Allow -Profile Any
Get-NetFirewallRule -DisplayName "MySQL 3306 (ZeroTier)" | Select DisplayName,Enabled,Direction,Profile
```

`-Profile Any` 不能省：ZeroTier 网卡常被 Windows 认成「公用网络」，只放行「专用」会导致组员一直 timeout。

### 8.4 组员侧

1. 装 ZeroTier（<https://www.zerotier.com/download/>），托盘右键 → **Join Network** → 填 `743993800f43676f`。
2. 把托盘里显示的 **Node ID（10 位）** 发群里，等管理员授权。
3. 状态变 `OK` 后拿到 `10.213.180.x`，先验端口：`Test-NetConnection 10.213.180.114 -Port 3306` → `TcpTestSucceeded : True`。
4. 连库跑后端：

```powershell
$env:DB_DSN='greentravel:greentravel@tcp(10.213.180.114:3306)/green_travel_points?parseTime=true&loc=Local&charset=utf8mb4'
cd apps\api
go run ./cmd/server
```

### 8.6 验证与排错

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 托盘 `ACCESS_DENIED` | 私有网络未授权 | 控制台 Members 勾 Auth；勾了无效则先删成员、托盘 **Disconnect** 再 Join，重新排队 |
| 托盘 `REQUESTING_CONFIGURATION` | 已授权，尚未握手 | 等 10–30 秒；检查能否连到 ZeroTier 的 planet |
| `Test-NetConnection` 超时 | 3306 入站未放行 / 网卡被当公用网络 | 跑 §8.3 命令，务必 `-Profile Any` |
| TCP 通但登录 `Error 1045` | 账号或密码不对 | 用 `greentravel`/`greentravel`；确认连的是 `green_travel_points` |
| `Error 1146 Table ... doesn't exist` | 迁移没跑全 | 按当前仓库从缺失的那组补跑到 `000011` 的 up（至少 `000003–000011`） |
| 昨天能连今天不行 | 主机休眠 / 退出 ZeroTier | 主机电源计划改「从不睡眠」，托盘保持运行 |

### 8.7 注意事项

- 免费版**每账号 10 个节点**，5 人足够；每台**新设备**都要重新报 Node ID、重新 Auth。
- 这台机器就是「服务器」：关 ZeroTier、休眠、断网，全组立刻掉线。
- MySQL 密码是 `greentravel`（弱密码）。只走 ZeroTier 内部可见尚可；**不要**把 3306 直接映射到公网。
- 部署到云主机时应换强密码，并同步改 `config.DefaultDatabaseDSN` 与 `deploy/docker-compose.yml`。
