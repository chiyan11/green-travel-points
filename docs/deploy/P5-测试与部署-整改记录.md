## 3. N04 · api 没有 healthcheck

改动（`deploy/docker-compose.yml`）：

```yaml
api:
  healthcheck:
    test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8080/healthz"]
    interval: 10s
    timeout: 3s
    retries: 5
    start_period: 20s
web:
  healthcheck:
    test: ["CMD", "wget", "-qO-", "http://127.0.0.1/"]
    interval: 10s
    timeout: 3s
    retries: 3
    start_period: 10s
```

`/healthz` 不依赖数据库，镜像内 `Dockerfile.api` 也有同名 HEALTHCHECK，compose 再显式声明一次，让 `web.depends_on.api: service_healthy` 有明确判定；`Dockerfile.web` 也加了镜像级 HEALTHCHECK。`docker compose ps` 三服务 healthy 的实跑见 §10。

## 5. N18 · smoke 永久改数据、可能打到共享库

改动（`scripts/smoke-deploy.ps1` 重写）：

- 默认**只读**：探针、公民/管理员登录、`/points/summary`、`/products`、`/admin/products`、`/admin/orders`、`/admin/audit-logs`、`/admin/config`，不发任何写请求，结束时打印“未写入任何数据”。
- 写路径要显式 `-AllowMutate`：建商品 → 改库存 → 下单 → 取消 → 调账 -5 → 参数 +20。
- 收尾在 `finally` 里，成败都跑：调账 **+5 冲正**、参数还原、商品 `PATCH {status: OFFLINE, name: 已归档冒烟商品-<stamp>}`，并断言 1001 余额回到开跑前、`部署冒烟商品-*` 无可见残留。
- 共享库保护：`ApiBase` 不是回环地址时默认 exit 1 并提示；确需远程要 `-AllowRemote`（写路径再叠 `-AllowMutate`）。
- 头部注释写明写路径会留下什么（`audit_log` 只追加，写路径必然新增，属验收证据）。

证据（本机临时 MySQL 3311 + 空库 11 组迁移 + seed + 真后端 `:18080`）：

```
# 只读（连续两次）
SMOKE OK（只读）：… 均可用；未写入任何数据。
audit 8 -> 8, balance=1200, 部署冒烟商品 residue=0

# 写路径（-AllowMutate，第一次、第二次各一遍）
PASS  1001 余额回到运行前：1200 -> 1200
PASS  无「部署冒烟商品-*」可见残留（本次运行新增：0 件）
SMOKE OK：建商品 / 改库存 / 下单 / 取消 / 调账 / 改参数 / 查审计 全部通过，数据已还原。

# 共享库保护
$ pwsh -File scripts/smoke-deploy.ps1 -ApiBase http://10.213.180.114:8080
拒绝执行：http://10.213.180.114:8080 不是本机回环地址。        exit=1
```

说明两点口径：

- 写路径的 `audit_log` 必然 +4（调账 1 + 冲正 1 + 参数变更/还原 2）。`audit_log` 是只追加表，后端没有删除端点，因此“审计无净增”只在默认只读模式下成立（实测两次只读 8→8）；要零写入就跑默认模式。
- 商品没有删除端点，收尾用“下架 + 改名归档”，`select ... where name like '部署冒烟商品-%'` 为 0 行；归档行本身保留（如需硬删除，要后端先补 DELETE 端点，属 N14 契约范围）。
