# 部署冒烟记录（P5 · 2026-11-27）

本文记录「Compose 全栈部署」这条链路的整改与验证证据，对应代码审查 P1-4：**compose 漏挂迁移、无 web 服务**。

> 时点说明：本文证据生成于 PR #48 合并前（9 组迁移，`000001`–`000009`）。PR #50 新增 `000010_trip_raw_points` 后，当前应为 10 组；容器冒烟与空库重放**尚未按 10 组重跑**，§2–§5 的 `9/9`、`9 组` 为当时原始输出，未改写。

## 1. 改了什么

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 迁移挂载 | 只挂 `000001`–`000005` | 挂全 `000001`–`000009`（`01_init` … `09_outbox_lease`） |
| web 服务 | 只有 `Dockerfile.web` + `nginx.conf`，未编入 compose | 新增 `web` 服务：多阶段构建 → nginx 托管 `dist/`，等 `api` 健康后启动 |
| 端口 | MySQL 写死 `3306:3306` | `${MYSQL_PORT:-3307}:3306`、`${WEB_PORT:-8088}:80`，避让本机已占端口 |
| 数据目录 | `./mysql-data` 固定 | `${MYSQL_DATA_DIR:-./mysql-data}`，便于切临时卷复验 |
| 防再漏挂 | 无 | 新增 `scripts/check-compose-migrations.ps1`，比对 `db/migrations/*.up.sql` 与 compose 挂载清单；已接入 `scripts/verify.ps1` 第 9 步 |

漏挂的后果有实证：`000006_point_batch_txn` 缺表时取消订单报 `Table 'point_batch_txn' doesn't exist`，`000007_audit_log` 缺表时调账、改参数报 500，`000008` 缺跑则 `carbon_record.rule_snapshot` 仍是旧拼串。原 compose 在后两条链路上必然失败。

## 3. 空库重放（替代容器实跑）

本机 Docker 引擎不可用（见 §6），因此按 **compose 完全相同的挂载顺序** 在一个空库上重放迁移，再用真实后端跑冒烟。库为本机 MySQL 8.0.46 临时实例（端口 3310，独立 datadir，`--initialize-insecure` 初始化，用完即停，不碰 3306 上的开发库）。

```sql
-- 建库后按文件名顺序执行
SOURCE db/migrations/000001_init.up.sql;
SOURCE db/migrations/000002_event_outbox.up.sql;
SOURCE db/migrations/000003_points_ledger.up.sql;
SOURCE db/migrations/000004_user_trip_carbon.up.sql;
SOURCE db/migrations/000005_mall_orders.up.sql;
```

## 6. 限制（如实记录）

本机 `docker version` 连接 `npipe:////./pipe/dockerDesktopLinuxEngine` 返回 500，启动 Docker Desktop 后仍 500；`wsl -l -v` 提示本机未安装 WSL2，因而无法执行 `docker compose up`。本文的迁移重放与冒烟是**同构替代验证**：迁移文件、执行顺序、连接串、种子、接口与真实 compose 一致，但没有容器网络与 nginx 转发这一层证据。

因此 P1-4 的「空卷 `docker compose up` 后 15 张表齐全 + 实跑日志」在本文档中只完成到「配置解析 + 同构重放 + API 冒烟」；容器实跑截图留待有 Docker 的机器按 §5 补做，属未闭环项，不记为已验收。
