#### P1-4（P1）Docker Compose 只挂载 000001–000005，缺 point_batch_txn 与 audit_log

- **配合**：P2、P3
- **位置**：deploy/docker-compose.yml:26-33。
- **问题说明**：MySQL 初始化只挂 5 个迁移，000006_point_batch_txn.up.sql 与 000007_audit_log.up.sql 未挂载；空卷启动后取消订单写 point_batch_txn、调账/配置写 audit_log 都会报表不存在；compose 也只有 mysql+api，没有 web/nginx。
- **修改建议**：补挂 000006、000007；已有数据卷需 down -v 后重建（仅本地库）；若承诺全栈 compose，补 web 服务，否则在 README 明确 compose 只起 MySQL+API。
- **验收标准**：空卷 docker compose up 后 15 张表齐全；取消订单、调账、配置变更不因缺表 500；README 对 compose 范围的描述与实际一致；保留一次实跑日志/截图。

#### P1-5（P1）CI 没有 MySQL 服务，10 个 repo 集成测试永远 SKIP

- **配合**：P2、P3、P1
- **位置**：.github/workflows/ci.yml:13-43；apps/api/internal/repo/orders_test.go、audit_test.go。
- **问题说明**：CI 没有 MySQL service、没有 REPO_TEST_DSN，repo 集成测试整包 SKIP；CI 绿灯没有证明订单事务、行锁、批次扣减、审计写入在真实 MySQL 上可用。
- **修改建议**：api job 增加 mysql:8.4 service，创建 _test 库，依次执行 db/migrations/*.up.sql，设置 REPO_TEST_DSN（库名以 _test 结尾），与单元测试同 job 跑 -race -coverprofile。
- **验收标准**：CI 日志显示 10 个 repo 测试实际执行而非 SKIP；集成测试失败会使 job 变红；MySQL 服务健康检查、建表、测试三步可复现；报告引用 CI 运行链接/截图。

#### P1-6（P1）测试报告两张表缺指导书要求的 4 列，属于格式硬伤

- **配合**：P1、P2、P3、P4
- **位置**：docs/实验报告-绿行积分.md:831-861；指导书测试章节（.cache/review/lab-guide.txt:247-279）。
- **问题说明**：表 4-1B 只有 5 列（被测单元/独立路径/输入/预期/结果），表 4-2 只有 5 列（功能/有效类/无效类/代表用例/结果）；指导书要求 9 列，缺输出内容、发现问题、测试时间、测试人，编号/路径标识也被合并。
- **修改建议**：按 9 列重写两张表；输出内容填实际命令/响应，不得编造；发现问题无则写“无”，有则写缺陷编号；测试时间/测试人按实际填写；表 4-1 的路径标识用基本路径编号。
- **验收标准**：两张表列名与指导书完全一致（9 列）；每行有实际输出、测试时间、测试人；发现问题列有内容或明确“无”；报告渲染后表头不丢列。
