### 3.2 待改问题

#### P0-1（P0）开发身份头在所有环境生效，前端默认注入用户 1，等于全站越权

- **位置**：apps/api/internal/httpserver/auth.go:171-187、189-199、279-302；apps/api/internal/httpserver/router.go:82-101；apps/web/src/lib/http.ts:33-40。
- **问题说明**：Require 在 Bearer 校验失败后无条件回退 X-User-Id，前端无 token 时主动设置 X-User-Id: 1；任意访客成为用户 1，改头即可冒充管理员 1002；verify 也没有 id>0 校验。
- **修改建议**：增加 AUTH_ALLOW_DEV_HEADER，默认 false，仅 APP_ENV=dev 且显式开启时允许身份头；prod 开启直接启动失败；Require 只在开关开启时读 X-User-Id；删除/改造 RequireUser；前端删除默认注入 1；verify 增加 id>0；同步 README/docs/api/README.md 身份约定。
- **验收标准**：匿名访问受保护接口返回 401；未开启开关时 X-User-Id: 1002 返回 401；开启开关的 dev 环境才可用身份头；前端请求不再出现默认 X-User-Id: 1；补 HTTP 测试覆盖 401/越权。

#### P1-3（P1）每日积分上限用客户端时间算窗口，且在锁账户前 SUM，可绕过、可并发超发

- **位置**：apps/api/internal/httpserver/trips.go:93-116、159-170、99。
- **问题说明**：dayStart 取客户端 traveledAt，未来时间使 SUM 为 0；SUM 在账户行锁前执行，并发请求可同时通过上限；INSERT IGNORE point_account 在事务内先共享锁再升级排他锁，存在 MySQL 1213 风险；scanTrip 把非 ErrNoRows 的 DB 错误当成“无旧行程”。
- **修改建议**：校验 traveledAt 不得晚于服务端当前时间（允许 5 分钟偏差）；INSERT IGNORE point_account 移到事务外；先 SELECT ... FOR UPDATE 锁账户，再用 CURDATE() 统计当日 TRAVEL 流水；scanTrip 区分 sql.ErrNoRows 与其他错误。
- **验收标准**：未来 traveledAt 返回 400；两个并发行程不能突破 500 分上限；并发测试无 1213；数据库错误返回 500 而不是继续插入；补未来时间/并发/DB 错误用例。

#### P1-10（P1）口令只用单次 SHA-256，抗暴力破解能力不足

- **位置**：apps/api/internal/httpserver/auth.go:305-325；db/seed/dev_demo.sql。
- **问题说明**：passwordHash 是 sha256(salt||password)，单轮、无工作因子；数据库泄露后弱口令/演示口令很快被还原。
- **修改建议**：改用 PBKDF2-HMAC-SHA256（Go 1.24 标准库 crypto/pbkdf2），迭代 600,000 次、32 字节输出；格式 pbkdf2$iter$salt$digest；开发期直接重建种子，不写旧 sha256$ 兼容分支；补正确/错误/篡改/低迭代测试。
- **验收标准**：新哈希格式可登录；旧 sha256$ 不再被接受（或按共享库约定完成迁移）；种子管理员/市民账号可登录；补 4 类口令测试；报告中写明算法与迭代次数。

#### P2-16（P2）Outbox Worker 的 handler 只打日志，事件被标记已投递；Dispatch 还在事务内调 handler

- **位置**：apps/api/cmd/server/main.go:96-99；apps/api/internal/repo/outbox.go:20-79。
- **问题说明**：main 启动的 worker handler 只 logger.Info 后返回 nil，Dispatch 成功后置 dispatched_at，但没有下游效果；Dispatch 持有事务和行锁期间调用 handler，慢 handler 会阻塞 outbox，崩溃还可能重复投递。
- **修改建议**：消费者未实现前不要启动 worker，或让 handler 返回错误使事件留在待投递/死信；采用“短事务认领→提交→执行 handler→成功标记”的租约模式；不要长时间持有 outbox 行锁；补 topic 常量与死信监控。
- **验收标准**：未实现消费者时事件不会被标记 dispatched；若启用 worker，handler 执行期间不持有 outbox 行锁；有“写入→消费→失败退避→死信”的集成测试；报告中的 EDA 描述与实现一致。

#### P2-19（P2）decodeJSONBody 没有请求体上限/尾随内容检查，部分 handler 忽略解码错误

- **位置**：apps/api/internal/httpserver/auth.go:329-333；apps/api/internal/httpserver/orders.go:82-98；apps/api/internal/httpserver/admin.go:139-159。
- **问题说明**：decodeJSONBody 无 MaxBytesReader、无尾随 token 检查；cancel/transition 直接忽略 Decode 错误，malformed JSON 被当成空 body，reason 丢失后继续执行。
- **修改建议**：decodeJSONBody 加 1 MiB 限制与尾随对象检查；cancel/transition 解码失败返回 400（io.EOF 可按业务决定是否允许空 body）；统一所有写接口走同一解码函数。
- **验收标准**：超过 1 MiB 的 body 返回 400/413；对象后追加 JSON 返回 400；cancel/transition 的 malformed JSON 返回 400 且不执行状态变更；补 HTTP 测试。

#### P2-22（P2）行程列表全量返回、dailyCarbon 天数无上限、INSERT IGNORE 吞错

- **位置**：apps/api/internal/httpserver/trips.go:99、123-127、227-268；apps/api/internal/httpserver/points.go:52-57。
- **问题说明**：List 无分页，返回全部行程并 LEFT JOIN point_txn；dailyCarbon 的 days 只处理 <=0，无上限；INSERT IGNORE trip_record 会把截断/唯一键错误降级为 warning；scanTrip 把所有错误当“没找到”。
- **修改建议**：List 至少 LIMIT 200，最好补 page/pageSize/total；dailyCarbon 限制 1–365，非法返回 400；trip_record 用普通 INSERT，唯一键冲突时 scanTrip 返回原行程；scanTrip 只把 sql.ErrNoRows 当不存在。dailyCarbon 部分与 P3 配合。
- **验收标准**：行程列表响应不超过 200 条或有分页字段；days>365 返回 400；重复行程返回原记录而不是吞错；DB 错误返回 500；补列表上限/天数/重复行程用例。

#### P3-23（P3）Outbox 退避位移可能溢出，错误截断可能切坏 UTF-8

- **位置**：apps/api/internal/repo/outbox.go:97-115。
- **问题说明**：retryDelay 用 1<<(attempts-1)，attempts 很大时位移溢出；truncateError 按字节截断 1024，可能切在多字节字符中间。
- **修改建议**：退避上限封顶（如 10 次/5 分钟）；截断按 UTF-8 边界回退；补 attempts=0、1、64 与中文错误串测试。
- **验收标准**：attempts=64 不溢出、退避不超过上限；中文错误串截断后仍是合法 UTF-8；补边界测试。

#### P3-24（P3）rule_snapshot 用字符串塞四个值再解析，hashTrip 距离只保留 3 位小数

- **位置**：apps/api/internal/httpserver/trips.go:149-150、331-352。
- **问题说明**：rule_snapshot 是展示串，parseRawPoints 反解析它拿 rawPoints，格式一改就断；hashTrip 用 %.3f 距离，理论上同用户/同方式/同纳秒时间、距离差 <1m 会碰撞。
- **修改建议**：rule_snapshot 改存 JSON（或拆列），响应直接用 grant.RawPoints；距离用 %.6f 或整数米；哈希加入客户端请求 ID/来源；补格式变更/边界测试。
- **验收标准**：代码不再反解析 rule_snapshot；响应 rawPoints 来自 grant；hashTrip 使用 6 位小数；补格式/边界测试；报告中的规则快照描述同步更新。
