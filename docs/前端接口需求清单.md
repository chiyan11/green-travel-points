# 前端接口需求清单（P4 → P2/P3）

> 用途：Sprint 1–2 联调前，把用户端 8 个页面需要的端点、字段、分页与错误码一次性提给后端。
> 口径来源：`docs/项目分工与迭代计划.md`、`apps/api/internal/domain`、`db/migrations/000001`。
> 约定：所有响应走统一壳 `{code, message, data}`；字段命名（camelCase / snake_case）以后端 OpenAPI 为准，前端用 `openapi-typescript` 生成类型，不手写 DTO。
> 前端现状：`apps/web/src/services/*` 为 MOCK 实现，联调时只替换函数体，页面不动。

## 0. 全局约定

| 项 | 约定 |
| --- | --- |
| 鉴权 | 登录后请求头 `Authorization: Bearer <token>`；401 前端清会话跳 `/login` |
| 分页 | 查询参数 `page`（从 1 起）、`pageSize`（默认 20）；响应 `{ items, page, pageSize, total }` |
| 时间 | 统一 ISO 8601（带时区），前端 `formatDateTime` 本地格式化 |
| 积分 | 整数 BIGINT，禁止浮点；碳排放 `DECIMAL(12,3)` 克 |
| 错误码 | 复用 `internal/httpserver/response.go`：OK / INVALID_ARGUMENT / UNAUTHORIZED / FORBIDDEN / NOT_FOUND / CONFLICT / INTERNAL / UNAVAILABLE |
| 幂等 | 上报行程带 `Idempotency-Key` 头；重复兑换请求同键只扣一次 |

## M1 用户与认证（P2）

### POST /api/v1/auth/register
请求：
```json
{ "nickname": "宋同学", "password": "至少6位" }
```
响应 data：`{ "userId": "u_xxx", "nickname": "宋同学", "token": "jwt..." }`
错误：`CONFLICT`（昵称/账号已存在）、`INVALID_ARGUMENT`（密码过短）。

### POST /api/v1/auth/login
请求：`{ "account": "账号", "password": "..." }`
响应 data：`{ "token": "jwt...", "user": { "userId", "nickname" } }`
错误：`UNAUTHORIZED`（账号或密码错误）。

### GET /api/v1/me
响应 data：`{ "userId", "nickname", "joinedAt" }`；401 时前端跳登录。

## M2 行程上报与碳核算（P2，复用 domain.EvaluateTrip）

### GET /api/v1/trips
查询：`page`、`pageSize`、`status=VERIFIED|REJECTED`、`from`、`to`（ISO 日期）。
响应 `items[]`：
```json
{
  "id": "trip_xxx",
  "mode": "subway",
  "distanceKm": 3.2,
  "traveledAt": "2026-10-18T08:10:00+09:00",
  "carbonSavedGrams": 483.2,
  "rawPoints": 4,
  "grantedPoints": 4,
  "cappedByDaily": false,
  "status": "VERIFIED"
}
```

### POST /api/v1/trips
请求：
```json
{ "mode": "subway", "distanceKm": 3.2, "traveledAt": "2026-10-18T08:10:00+09:00" }
```
- `mode` 枚举：`walk | bike | subway | bus | shared_bike`
- `distanceKm`：0.1–100（含端点），非法返回 `INVALID_ARGUMENT`
- 响应 data 同上单条 Trip；必须返回 `rawPoints` 与 `grantedPoints` 两个值，前端要展示"原始/实发"和封顶原因
- 幂等：同 `userId + trip_hash` 重复上报只产生 1 条记录、1 笔流水，重复提交返回原记录（`CONFLICT` 或 200 原样返回，请后端定一种并写进 spec）

## M3/M5 积分账户与流水（P2+P3）

### GET /api/v1/points/summary
```json
{
  "balance": 1280,
  "totalCarbonSavedGrams": 2435.2,
  "earnedThisMonth": 22,
  "earnedToday": 4,
  "dailyCap": 500
}
```
不变量：`balance == Σ(point_txn.amount)`，请提供对账口径。

### GET /api/v1/points/transactions
查询：`page`、`pageSize`、`type=EARN|SPEND|EXPIRE|ADJUST|REVERSE`。
`items[]`：`{ id, type, amount(正得负耗), balanceAfter, reason, refType, refId, createdAt }`。

## M6 商品与库存（P3）

### GET /api/v1/products
查询：`page`、`pageSize`、`category`、`keyword`、`onlyInStock=true`。
`items[]`：`{ id, name, description, pointsPrice, stock, category, imageUrl?, active, limitPerUser? }`。

### GET /api/v1/products/{id}
单条商品；下架/不存在返回 `NOT_FOUND`。

## M7 兑换下单与订单状态机（P3）

### POST /api/v1/orders
请求：`{ "productId": "p_1", "receiver": "本人" }`
- 预校验失败：积分不足 `CONFLICT`（或自定义 INSUFFICIENT_POINTS）、库存不足 `CONFLICT`、超限兑 `INVALID_ARGUMENT`
- 成功响应：`{ id, productId, productName, pointsSpent, status: "PENDING", receiver, createdAt, updatedAt }`
- 扣减/冻结走事务 + 行锁，禁止先查后写；并发不超卖

### GET /api/v1/orders
查询：`page`、`pageSize`、`status=PENDING|PAID|SHIPPED|COMPLETED|CANCELLED`。

### POST /api/v1/orders/{id}/cancel
仅 `PENDING` 可取消；返还积分、恢复库存、写冲正流水；非法跃迁返回 `CONFLICT`。

### 订单状态机（前端按钮按此禁用）
```
PENDING ──→ PAID ──→ SHIPPED ──→ COMPLETED
   │          │
   └──→ CANCELLED ←──┘（PAID 是否可取消请后端确认，原型先只开放 PENDING）
```
