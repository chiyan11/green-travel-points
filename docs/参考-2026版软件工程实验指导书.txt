软件工程课题组
二零二六
一、课程目标
　　　1、使学生能够按照特定的软件选题调研分析相关软件的系统需求，并应用UML建立软件分析模型。
　　　2、使学生能够结合数据库、现代Web开发框架及API设计等相关知识，设计并实现能够满足问题描述和约束条件的软件系统解决方案；能够应用UML等建模工具建立软件设计模型，并依据敏捷开发理念进行系统原型开发与迭代。
　　　3、通过实验分组安排，使学生具有通过团队配合进行有效的分工，并能协调合作共同完成软件项目目标的能力。
　　　4、通过规范的实验报告撰写要求，使学生了软件科技文档的书写要求，并能够准确规范的撰写分析设计文档。
　　　5、使学生能够在软件开发的各环节合理使用AI辅助工具，并建立"AI辅助，人决策"的工程意识，能够对AI生成的内容进行审查、修改和验证。
二、实验环境
1.建模工具：StarUML、Rational Rose或PlantUML等其他UML建模工具
2.协作与版本控制：Git + GitHub / GitLab / Gitee 
3.开发工具可选，鼓励使用新技术栈，如：
前端：Vue.js / React / Angular (任一现代框架) 或 Bootstrap。
后端：Spring Boot (Java) / Express.js (Node.js) / Django (Python) / .NET Core (C#)。
数据库：MySQL / MongoDB。
文档工具：Microsoft Office / WPS Office / Markdown
部署：鼓励使用Docker容器化，并可部署至云平台（如阿里云、腾讯云、Heroku）的试用套餐
推荐的AI辅助工具：GitHub Copilot、Cursor、通义灵码、文心快码
三、实验要求
　　　1、4-5个人自愿结为一个项目小组，每组指定一名组长，必须使用Git进行版本控制，并有清晰的Commit记录，以体现协作过程。
　　　2、每组从实验题目中任选一题，也可由小组经协商并经指导教师确认符合实验要求后确定自选题目。
　　3、采用敏捷开发模式，以1-2周为一个迭代周期（Sprint），每个迭代结束时需提交可工作的软件增量。鼓励使用看板（如GitHub Projects）进行任务管理。
　　4、系统建模要求采用UML建模方法，鼓励绘制用户故事地图辅助需求分析。
　　5、每个小组提交一份完整的实验报告（提交打印和电子两种形式），文档格式、内容参照附件实验报告样本。
　　6、组长需在报告中提供基于Git提交记录和任务完成情况的组内互评表，作为评分重要依据。
　　　7、鼓励在实验各环节合理使用AI工具，但须遵守以下原则：
　　　（1）AI生成的代码、测试用例、模型初稿，必须经过人工审查、修改和验证，不得直接复制粘贴作为最终成果。
　　　（2）在实验报告中须如实注明AI使用情况：用了什么工具、在哪个环节使用、做了什么、人工做了哪些修改。
　　　（3）答辩时需能解释所提交代码/模型的每一处设计决策，不得以"AI生成的"作为无法解释的理由。
四、实验内容
　　　1、实验一：需求分析与迭代规划
　　　按照特定的软件选题，调研分析、建立用户故事地图、确定软件的系统需求，并应用UML建立软件问题模型。
　　　2、实验二：系统设计与技术选型 
　　　应用软件设计知识设计出能够满足问题描述和约束条件的软件系统解决方案，并应用UML建立软件设计模型。
　　　3、实验三：系统原型构建与实现
　　　应用适当的软件开发工具进行软件原型搭建，并选取部分模块编码实现。（鼓励使用AI辅助生成代码骨架和测试代码，但须经过人工审查和修改，并在报告中注明使用情况。）
　　　4、实验四：软件测试与部署
　　　设计软件测试方案，并对已实现的系统模块设计测试用例，实施测试，分析测试结果并写出部署方案。（鼓励使用AI辅助生成测试用例初稿，但须人工审核测试覆盖的完整性，补充AI遗漏的业务场景，并在报告中注明使用情况。）
五、实验项目选题
1. 数字银行核心业务模拟系统
　　　总体描述： 打造一个模拟现代数字银行核心业务的分布式系统，涵盖存款、取款、转账、风控等关键金融业务。项目组需要构建一个高内聚、低耦合的微服务架构，以应对复杂的业务规则和高一致性要求。
    【分析与设计重点】：分析存款、取款、跨行转账、风控等核心业务的完整流程与异常场景；设计微服务架构（如用户、账户、交易服务），并明确服务边界与接口，用部署图展示物理架构；建立精确的领域模型，并对“账户”、“交易流水”等核心实体进行建模。
    【实现与测试要求】：实现关键业务服务接口，完成至少一个端到端业务流程（如存款）；编写测试用例，验证核心业务逻辑的正确性与服务间调用的可靠性。
2.航空旅行一站式服务平台
　　　总体描述： 打造一个整合机票、酒店、景点门票的综合性旅行服务平台。项目组需要实现智能航班推荐、动态票价模拟、在线值机、行程规划等功能，为旅客提供一体化的出行解决方案。
    【分析与设计重点】：分析旅客、旅行社等多角色用例；梳理航班查询、预订、支付、值机等复杂业务事件流；设计前后端分离架构，并规划与外部模拟API（如支付、航信）的集成方案；可以使用序列图清晰描述关键交互场景。
    【实现与测试要求】：实现航班搜索与展示、用户订单管理核心页面与后端接口；模拟完成从查询到订单创建的完整流程；对搜索性能、订单状态流转进行功能测试。
3.高校学生成长与职业发展数据中台
　　　总体描述： 构建一个汇聚学生在校期间全维度数据（学业、科研、实践等）的数据中台。项目组旨在通过数据整合与分析，形成学生个人能力画像，并为职业发展推荐提供数据支撑。
    【分析与设计重点】：分析多源数据（学业、实践等）的整合与标准化需求；设计统一的学生数据模型与画像计算规则；规划中台为前台应用提供数据服务的能力与API。在架构设计上，需明确采用分层架构，区分数据采集层、数据处理层、数据服务层与前端应用层，并用包图表示逻辑架构。
    【实现与测试要求】：实现数据录入、存储与核心画像指标（如综合成绩）的计算功能；提供至少一种数据查询服务接口；测试数据计算的准确性与接口服务的正确性。
4.智慧仓储与物流协同系统
　　　总体描述： 开发一个支撑现代智能仓库高效运营的管理系统，并与物流环节深度协同。项目组需要实现从入库、在库管理到出库发货的全链路数字化管理。
    【分析与设计重点】：分析入库、拣选、盘点、出库等全链路作业流程；设计库存、货位、单据等核心领域模型；规划与模拟物流系统的API交互协议。在架构设计上，需采用事件驱动架构来处理库存变更、订单状态更新等业务事件，并用部署图展示系统与物联网设备的可能部署方式。
    【实现与测试要求】：实现库存管理、订单处理核心功能；模拟完成一次从入库到出库的完整物流跟踪流程；测试库存数据在各类操作下的准确性与一致性。
5.在线编程评测与考试平台
　　　总体描述： 创建一个支持编程题在线作答、自动评测与考试管理的专业平台。项目组需要解决代码安全运行、并发评测和公平性保障等核心挑战。
    【分析与设计重点】：分析教师、学生、管理员的核心用例与业务规则；设计试题、试卷、考试记录、评判任务等复杂领域模型；对“考试”进行状态建模，并设计高并发提交下的任务调度方案。在架构设计上，建议采用带有消息队列的生产者-消费者模式来处理高并发的评测任务。
    【实现与测试要求】：实现题库管理、在线考试与代码提交功能；集成或模拟一个简单的代码评测引擎；对考试流程和代码评测功能进行充分的功能测试。
6.云原生微服务架构实践：在线商城系统
　　　总体描述： 以云原生技术栈为核心，从零开始设计与实现一个完整的在线电商系统。项目组需要深入实践微服务拆分、容器化部署与可观测性等现代化软件开发流程。
    【分析与设计重点】：完成彻底的微服务拆分方案（如商品、订单、用户等）；设计服务间的通信、数据一致性及网关路由方案；绘制清晰的系统逻辑与物理架构图。
    【实现与测试要求】：实现至少三个核心微服务，并完成服务间联调，验证一个核心业务流程（如用户下单）；进行简单的压力测试，验证系统的可扩展性。
7.物联网边缘计算平台（智慧农业/智慧教室场景）
　　　总体描述： 构建一个基于物联网技术的智能监控与自动化控制系统，可在智慧农业或智慧教室场景中任选其一。项目组需要实现设备管理、数据采集、智能告警与自动化控制闭环。
    【分析与设计重点】：分析设备管理、数据采集、自动化规则等核心需求；设计“设备-数据-规则”模型，并使用活动图描述复杂的自动化控制逻辑；在架构设计上，建议采用分层架构，并区分边缘设备层、网络通信层、平台服务层与应用层，用部署图进行描述。
    【实现与测试要求】：实现设备数据接收、存储与可视化展示；配置并触发至少一条自动化控制规则；测试数据流的完整性与规则触发的准确性。
8.企业级协同办公与知识库平台
　　　总体描述： 打造一个支持多人实时协作、模块化编辑的企业级知识库与文档平台。项目组需要攻克富文本编辑、权限管理与实时协作等核心技术点。
    【分析与设计重点】：分析文档权限体系、版本管理、实时协作等复杂业务需求；设计支持块编辑的富文本数据模型及权限管理模型；可以用序列图描述多用户协同编辑的交互过程。在架构设计上，建议采用CQRS架构模式分离读/写操作，以优化复杂查询性能，并用包图展示上下文映射。
    【实现与测试要求】：实现文档的创建、编辑与权限控制基础功能；可模拟实现简单的实时更新提示；对权限管理和文档操作进行全面的功能测试。
9.实时数据流处理与可视化系统
　　　总体描述： 建立一个端到端的实时数据处理与可视化大屏系统。项目组需要构建从数据模拟生成、实时计算到动态图表展示的完整数据流水线。
    【分析与设计重点】：分析数据从产生、采集、计算到展示的数据流；设计系统各组件（如消息队列、流处理、前端）的架构与接口，在架构设计上，建议采用Lambda架构或Kappa架构处理实时与批处理数据流，并用数据流图展示数据处理管道；定义实时计算指标的数据模型与更新机制。
    【实现与测试要求】：搭建完整的数据流水线，实现从模拟数据生成到前端图表展示的全过程；验证数据处理流程的正确性与实时性。
10.智能客服工单管理与溯源系统
　　　总体描述： 打造一个集成AI能力的智能客服工单管理平台，实现用户问题自动分流、工单全生命周期追踪和会话溯源分析。项目组需要构建一个能有效提升客服效率与用户体验的系统。
    【分析与设计重点】：分析用户、客服、管理员等多角色在工单创建、分配、处理、升级、关闭等环节的交互与业务规则；设计工单、会话、知识库条目等核心领域模型；在架构设计上，建议采用事件驱动架构，设计工单状态变更时触发通知、升级等事件的流程，保证系统的解耦与响应能力，规划与AI语义理解模块的接口。
    【实现与测试要求】：实现工单创建、分配、状态更新与查询的核心流程；集成或模拟一个简单的意图识别AI服务，实现工单自动分类；测试工单流转的正确性与AI分类的准确性。
11.智慧医院门诊候诊与用药指导系统
　　　总体描述： 设计并实现一个优化医院门诊流程的智慧系统，为患者提供实时候诊队列查询、智能分诊引导和用药指导服务。项目组需要关注系统在真实医疗环境下的易用性与可靠性。
    【分析与设计重点】：分析患者、护士、药师等角色在分诊、叫号、药品发放与咨询中的用例；设计科室、患者队列、处方、药品知识库等核心领域模型；设计确保用药安全性的业务规则，在架构设计上，建议采用清晰的分层架构，并特别设计一个高可用、高实时性的服务层，以支撑候诊队列的实时更新与广播。
    【实现与测试要求】：实现患者挂号加入候诊队列、队列状态实时查询与通知的核心功能；构建一个简单的药品知识库并提供查询接口；测试队列更新与通知的实时性以及药品信息查询的准确性。
12.智慧医疗在线问诊与处方流转平台
　　　总体描述： 构建一个连接患者、医生与药房的在线医疗服务生态系统。项目组需要实现在线问诊、电子处方开具、处方审核与流转至合作药房的核心业务闭环，并重点关注医疗数据的安全性与隐私保护。
  【分析与设计重点】：分析患者、医生、药师、管理员等多角色的复杂用例与权限边界；设计问诊会话、电子处方、药品目录等核心领域模型，并对“处方”状态（如待开具、待审核、已流转、已核销）进行严谨的生命周期建模（可以采用UML状态图）；在架构设计上，建议采用领域驱动设计（DDD）的思路划分核心子域，并采用分层架构清晰分离医疗业务逻辑与数据持久化层，确保核心业务的可维护性与安全性。
  【实现与测试要求】：实现用户注册认证、在线图文问诊、处方草稿创建与编辑等核心功能；模拟完成从问诊到处方开具并流转的业务流程；对用户权限控制、处方状态流转和关键业务接口进行充分的功能与安全测试。
13.云边协同的智能安防监控系统
　　　总体描述： 设计并实现一个综合利用云端算力与边缘设备能力的智能安防系统。项目组需要处理视频流的接入、在边缘端进行初步分析（如移动侦测），并在云端完成更复杂的AI识别（如人脸识别、异常行为检测）与告警通知。
   【分析与设计重点】：分析视频设备管理、视频流处理、AI事件识别与告警推送的业务流程；设计“摄像头”、“视频流”、“分析任务”、“告警事件”等核心领域模型；在架构设计上，须采用云边协同架构，明确划分边缘侧（负责数据采集与轻量计算）与云端（负责聚合、存储与复杂分析）的职责，并设计两者之间的高效、可靠通信机制。
    【实现与测试要求】：实现设备管理、视频流拉取与展示基础功能；模拟或集成一个简单的AI识别服务（如识别图片中是否有人），并触发告警；测试从边缘事件产生到云端告警形成的完整链路的及时性与正确性。
14.碳中和主题的城市绿色出行积分系统
　　　总体描述： 开发一个鼓励市民采用绿色出行方式（如公交、地铁、骑行）的积分激励平台。项目组需要实现出行数据采集（模拟）、碳减排量计算、积分累积与兑换，以及积分商城的运营管理。
    【分析与设计重点】：分析用户、运营管理员、商户等多方参与者的利益诉求与系统功能；设计“用户账户”、“出行记录”、“碳积分”、“商品”等核心实体及其关联关系；制定并建模积分生成、消耗与清算的业务规则；在架构设计上，建议采用事件驱动架构（EDA）来处理用户出行后触发的积分发放、清算等一系列后续业务，实现系统组件间的解耦。
    【实现与测试要求】：实现用户行程上报（模拟）、个人积分查询与积分商城商品浏览兑换的核心流程；确保积分计算与消耗的准确性和一致性；对积分核心逻辑进行全面的单元测试与集成测试。
15.基于区块链技术的数字资产存证系统
　　　总体描述： 探索区块链技术的应用，构建一个用于重要电子文件（如电子合同、版权证书）哈希值存证的系统。项目组不需要实现完整的区块链，但需理解并模拟区块链的核心概念，实现数据上链（模拟）、存证查询与验证等功能。
    【分析与设计重点】：分析文件上传者、验证者等角色用例；设计“存证记录”、“区块”、“链”等核心领域模型，清晰表达其不可篡改的特性。在架构设计上，需设计一个模拟的区块链服务层，该层应提供生成区块、构建哈希链、验证数据完整性等核心接口，并在整体架构中明确其位置。
    【实现与测试要求】：实现文件上传生成哈希、将存证信息（模拟）写入“区块”、以及基于链式结构验证文件是否被篡改的核心流程；测试存证与验证流程的正确性，并演示对篡改文件的识别能力。

16.敏捷研发项目管理平台
　　　总体描述： 为软件研发团队量身打造一个深度契合敏捷开发流程的项目管理工具。项目组需要将敏捷理念转化为系统功能，并实现与代码仓库的联动。
    【分析与设计重点】：深度分析敏捷开发流程，建模产品Backlog、迭代、任务等核心概念；设计与GitLab/GitHub等外部系统的数据同步方案；设计燃尽图等报表的数据生成逻辑；在架构设计上，采用经典的MVC或前后端分离架构，并清晰定义与外部系统的集成边界，用部署图展示系统拓扑。
    【实现与测试要求】：实现项目、迭代和任务管理核心功能；能够生成基本的项目报表（如燃尽图）；测试核心项目管理流程的顺畅性。
17.自选课题
　　　总体描述： 鼓励学生小组从自身兴趣或行业观察出发，提出具有创新性和实践价值的自选课题。选题应能充分展现业务分析、系统设计与软件建模的综合能力。
    【要求】：须经指导教师确认课题在业务复杂性、系统设计空间和建模价值上达到实验要求。项目报告必须包含完整的UML分析设计模型，并明确说明所采用的系统架构风格及其合理性。
