### P2（1 项）

#### P2-20（P2）前端用 crypto.randomUUID() 生成幂等键，非安全上下文（局域网 HTTP）会直接抛错

- **配合**：P5
- **位置**：apps/web/src/services/orders.ts:35-41。
- **问题说明**：crypto.randomUUID() 只在安全上下文（HTTPS/localhost）可用；答辩/联调常用 http://192.168.x.x:5173，调用会抛 TypeError，下单请求还没发出就失败。
- **修改建议**：写 newIdempotencyKey()，优先 randomUUID，否则用 crypto.getRandomValues 生成 16 字节 hex；补 vitest 覆盖 fallback。
- **验收标准**：在非安全上下文（LAN HTTP）下单不再抛 TypeError；fallback 生成 32 位 hex；vitest 覆盖 randomUUID 缺失场景。

### P3（1 项）

#### P3-25（P3）Token 存 localStorage，XSS 可直接窃取；无 HttpOnly 保护

- **配合**：P2、P5
- **位置**：apps/web/src/lib/session.ts:9、13、26；apps/web/src/lib/http.ts:35-37。
- **问题说明**：gtp_session 存 localStorage，任何 XSS 都能读走 token；token 有效期 2 小时，足够做管理员操作。
- **修改建议**：长期方案后端签发 HttpOnly/Secure/SameSite Cookie，前端 credentials: include，配套 CSRF token；短期加 CSP、禁止 dangerouslySetInnerHTML、缩短 token 有效期；若本轮不实现，必须在报告安全限制中写明取舍。
- **验收标准**：若实现 Cookie，JS 不可读 token 且 CSRF 有防护；若暂不实现，报告中记录风险、缓解措施与后续计划；前端不再把 token 放进可被任意脚本读取的全局位置（至少完成 CSP/转义评估）。
